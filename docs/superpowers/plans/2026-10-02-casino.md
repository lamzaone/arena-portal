# Portal Casino Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add four playable casino games using existing portal Tokens and preserve the requested commercial-slot integration dependency without accepting unsupported wagers.

**Architecture:** Pure native game engines feed a durable casino repository. The repository reuses existing wallet transaction helpers through a small exported transaction interface; route handlers reuse Steam/CSRF guards. React clients render server outcomes and poll the shared crash clock. Requested provider slots remain unavailable until real operator API access and the wallet protocol are supplied.

**Tech Stack:** Existing Next.js 16, React 19, TypeScript, mysql2, node:test, Playwright, Node crypto; no new production dependency.

**Spec:** `docs/superpowers/specs/2026-10-02-casino-design.md`

## Global Constraints

- All native game stakes and payouts use `portal_token_accounts` and the immutable `portal_token_ledger`.
- Minimum stake is 2 Tokens and the configurable default maximum stake is 10,000 Tokens.
- All Token values are safe integers. Blackjack stakes must be even to pay 3:2 exactly.
- Expose no live hidden cards, shuffle order, or crash point.
- Commercial slots may use portal Tokens only through a verified authorized provider wallet API. No demo-to-token bridge or fabricated protocol. Without API access, slots stay unavailable and cannot accept stakes.
- Use a local test database only for integration; never apply migrations to a hosted database.
- No new production dependency. Do not modify CS2 plugins or remotely deploy.
